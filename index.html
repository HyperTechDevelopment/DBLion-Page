How the guard works

Three moves, one human in charge

  1. 01

    AI proposes

    The copilot drafts SQL with live schema context. Text only, with no execution path.

  2. 02

    Guard checks

    Read-only fence, single-use token and native confirmation bind the exact statement.

  3. 03

    You execute

    Nothing runs without your action. Grants stay the final boundary.

The guard

The boundary is explicit

  • READ-ONLYAI never executes. You approve every write.
  • LIMITHonest limits: unsigned installer, no auto-update; Firebird without row-edit/CSV, SQL Server without CSV.
